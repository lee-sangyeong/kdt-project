Python GUIIndividual Build

차량 데이터를 사용자가 탐색 가능한 GUI로 구현

Python Tkinter로 현대자동차 차량 정보를 조회하는 데스크톱 프로그램을 구현했습니다. 연료 타입 선택, 차종 목록 조회, 상세 제원과 차량 이미지 확인까지 이어지는 흐름을 만들고, 폴더 기반 데이터 구조와 예외 처리를 함께 설계했습니다.

My Scope
화면 구조와 데이터 로딩을 직접 연결
연료 타입 선택 화면, 차종 목록 화면, 상세 화면을 분리하고 Frame 전환으로 흐름을 구성했습니다. 데이터는 코드에 직접 박지 않고 data_Hyundai 폴더 하위의 연료별·차종별 파일을 읽도록 만들었습니다.
Decision Point
파일이 달라도 동작하는 조회 구조
차량 제원 파일이 spec.json으로 제공되면 JSON을 우선 읽고, 없으면 spec.txt, 그마저 없으면 다른 텍스트 파일을 탐색하는 fallback을 두었습니다. 이미지 누락과 경로 오류도 프로그램이 멈추지 않도록 처리했습니다.
핵심: 단순 문법 실습을 넘어, 데이터 구조·파일 입출력·화면 전환·예외 처리를 하나의 작은 업무 도구 형태로 묶은 프로젝트입니다.

03

결과와 구현 근거

User Flow
연료 선택에서 상세 조회까지 이어지는 구조
사용자는 홈 화면에서 연료 타입을 고르고, 목록 화면에서 차종을 선택한 뒤 상세 화면에서 제원과 이미지를 확인합니다. 검색·조회·상세 확인이라는 업무 도구의 기본 흐름을 GUI로 구현했습니다.
Robustness
자료 누락 상황에서도 앱이 유지됨
파일이 없을 때 에러로 종료되는 대신 안내 메시지를 표시합니다. 실무의 내부 도구도 데이터 품질이 항상 완벽하지 않기 때문에 이런 방어 로직이 중요합니다.
포트폴리오 해석: Python 기초 프로젝트지만, 자동차 데이터를 화면으로 보여주는 방식, 폴더 기반 데이터 관리, 예외 처리 습관을 보여주는 출발점입니다.

05

직무 연결과 개선 방향

자동차·제조 기업의 내부 업무 도구는 데이터를 단순히 저장하는 것보다 사람이 확인하고 조작할 수 있는 화면으로 연결하는 능력이 중요합니다. 이 프로젝트는 Python으로 데이터 로딩과 사용자 화면을 직접 연결한 기초 구현 역량을 보여줍니다.
— Python GUI 프로젝트 회고
한계
데이터가 파일·폴더 구조에 의존하므로 차량 수가 늘어나면 관리가 어려워질 수 있습니다.
개선
SQLite 또는 CSV/DB 기반 관리로 전환하면 검색, 필터, 정렬 기능을 안정적으로 추가할 수 있습니다.
확장
차량 가격, 연비, 차급 비교 기능을 붙이면 이후 차량 추천·비교 대시보드와 연결됩니다.
